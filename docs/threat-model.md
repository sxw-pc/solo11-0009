# 脱敏边界与重识别风险（Threat Model）

maskline 是一个本地工具，不是合规认证产品。它降低数据交付中的直接暴露，但不能保证脱敏后的数据绝对无法重识别。

## 信任边界

```
源数据（高敏感） --只读--> maskline
                              ├── 目标库（应交付）
                              ├── 报告（应检查后交付）
                              └── 映射库 / 密钥 / 审计头（不得交付）
```

需要按最敏感资产保护：

1. **密钥文件**：`MASKLINE_SECRET_FILE` 指向的文件。持有者可对候选值重算 HMAC。
2. **假名映射库**：`data/pseudomap.sqlite`。持有者可还原全部 `pseudonym` 值，等同于密钥。
3. **源数据与中间产物**：源库、运行目录、检查点、manifest 和报告样本。
4. **审计日志与头锚点**：日志描述处理过程，头锚点用于检测尾部截断。

## 假名映射表 = 密钥

`pseudonym` 是**可逆映射**，不是单向加密：

- 映射库以明文保存原文与 token；从输出库拿到 token 后可用受控还原流程查询原文。
- 映射库必须与脱敏输出物理分离、单独访问控制、单独备份和销毁。
- 本期不提供映射表加密存储，只建议使用文件系统权限（创建时尝试设为 `0600`）。
- 如果映射库泄漏，还原仍受**双人受控还原**约束：仅凭映射库无法通过命令行还原，
  还需要有效的操作员申请与另一名复核人的授权（见下文"受控还原的威胁模型"）。
  但能直接打开 SQLite 文件读取明文条目的主体不受此约束，因此映射库仍按密钥级资产保护。
- 如果映射库丢失，还原能力即丢失；token 本身仍然稳定，但无法从 token 反推原文。

## 受控还原的威胁模型

受控还原（见 `docs/controlled-reveal.md`）在"映射库等同密钥"之上再加一道双人闸门。
本节明确它能防什么、不能防什么。

### 信任根与对称签名的取舍

- 系统完全离线、无 CA、无新第三方依赖，身份与授权只能用本地密钥文件实现。
- 签名采用标准库 HMAC-SHA256（对称），因此**验证方必须持有同一把密钥**。这不是
  非对称数字签名：拿到某身份密钥文件的人既能替它签名也能验它的签名。
- 双人控制的根信任是：operator 与 reviewer 两把密钥由**两个不同的人分别保管**，
  且 keyring 目录与密钥文件权限为 `0700`/`0600`。代码强制角色与身份分离，但无法
  强制物理保管。若单人同时取得两把私钥，即可伪造完整授权链。
- keyring 清单只存密钥指纹与角色状态，不含秘密材料；每个密钥文件带自校验 MAC，
  被替换为外部密钥时加载即失败。

### 已覆盖的攻击

- **授权/申请篡改**：HMAC 覆盖规范 message，任何字段改动都使标签失效；授权还内含
  申请的 `request_hash`，申请被改无法复用旧授权。
- **授权过期与时钟回拨**：有效期受 MAC 保护的单调时钟锚点约束；回拨系统时钟、
  篡改锚点文件都会被检测并拒绝；执行中每行复查到期，到期即中止并清理临时明文。
- **重放**：授权在产出明文前以 `reveal-claimed` 原子落链，哈希链防删改，同一
  `authorization_id` 第二次出现即拒并留 `reveal-denied`。
- **批次/范围越界**：执行时现场重算数据集指纹并核对 manifest 的 `run_id`，换批次、
  加表加列、超 `max_rows` 全部拒绝。
- **职责混同**：operator 密钥不能签授权、reviewer 密钥不能签申请，且两 kid 必须不同。
- **密钥生命周期**：`rotated` 密钥停签但历史签名可验，`revoked` 密钥连历史签名一并拒绝。

### 未覆盖 / 残余风险

- 拥有本机高权限、能同时读取全部 `0600` 密钥与映射库、并能改写审计日志、头锚点和
  时钟锚点的主体，可绕过全部软件控制。缓解依赖 OS 权限、全盘加密、只追加或异地
  日志归档，而非本工具自身。
- 对称体系下没有公钥签名那种"签发者无需向验证者暴露私钥"的属性；跨组织转移授权
  不在设计范围内。
- 授权签发后在过期前无法在线撤销（无服务器）；应急通过 `revoke` 复核人密钥使其
  历史签名立即失效。
- 安全删除在日志/写时复制文件系统上无法保证物理擦除，只能保证失败后无明文路径残留。

## 加盐哈希的暴力破解边界

`hash` 使用 HMAC-SHA256，不是口令哈希：

- 手机号、身份证号、卡号等空间有限，攻击者若获得密钥，可以枚举候选值并重算哈希。
- 攻击者若未获得密钥，HMAC 仍显著高于无密钥哈希，但低熵原文仍可能通过泄露的辅助信息缩小候选空间。
- 相同原文在同一密钥下产生相同哈希，可能被用于跨表关联。
- 对高敏感字段优先使用 `pseudonym`（可还原）或 `nullify`，不要误以为 `hash` 等于匿名化。

## 泛化与重识别

- 日期泛化到月/季度/年、年龄分段、金额区间、地址到城市，仍然可能因稀有组合而定位到个人。
- 地址只保留城市时，若数据集中某个城市只有一条记录，仍可能直接识别。
- 金额/年龄取整或分段无法替代移除直接标识符。
- 多列组合、时间序列、与外部公开数据连接都可能造成重识别。maskline 不做 k-匿名、差分隐私或 l-多样性保证。

## 遮蔽与前后缀泄露

- `mask` 保留前后缀会泄露部分信息；例如保留身份证后四位、手机号前三位，结合其他字段可能足以关联。
- 短字符串在前后缀之和大于等于长度时会被整串遮蔽；这是为了避免误以为已脱敏。
- 空串与 `NULL` 在多数转换器中原样保留，可能暴露“缺失模式”。

## 审计与日志

- 审计日志是追加式 JSONL，每条包含前一条的哈希，`audit --verify` 能定位被修改的条目。
- 链本身不是带密钥的签名；拥有日志写权限的人可以重算整条链。`audit.jsonl.head` 锚点用于检测尾部截断，但攻击者若能同时改写日志与头锚点，仍可伪造一致的链。应把日志和头锚点写到只追加存储或定期异地归档。
- 审计日志不含原文，但含路径、策略指纹、输出哈希和处理计数；这些仍属于内部元数据。

## dry-run 不产生写入

`dry-run` 只读取源数据与密钥并统计。它不写目标库、映射、检查点、manifest、报告、审计或元数据库。dry-run 展示的假名 token 不代表已写入映射，不能用于还原。

## 源数据保护

- SQLite 源使用 `mode=ro` 与 `PRAGMA query_only` 打开。
- 运行器拒绝把输出路径设为源文件路径。
- 报告示例只展示脱敏后的值；疑似敏感但未配置策略的列在报告中隐藏原值。
- 这些措施不能替代操作系统权限、磁盘加密、访问审计和备份策略。

## 本工具不适用的场景

- 需要法律意义上的匿名化/去标识化认证；
- 需要处理非结构化文档、图片、音频、PDF 内容；
- 需要连接 MySQL / PostgreSQL / 数据仓库或实时消息系统；
- 需要多用户、RBAC、审批流、Web UI 或 HTTP API；
- 需要分布式执行、定时调度、增量订阅、数据血缘；
- 需要 k-匿名、差分隐私等正式隐私模型；
- 需要把脱敏数据与映射库、密钥一起交付。

## 推荐操作

1. 交付前运行 `scan` 与 `--dry-run`，复核高/中置信度字段与未配置告警。
2. 只交付 `data/out/` 中所需文件；不要打包 `data/` 整个目录。
3. 报告和审计日志在交付前单独审查。
4. 映射库与密钥分开保管，限制访问并记录访问日志。
5. 使用独立随机密钥；演示自动生成的 `data/demo-secret.txt` 不得用于真实数据。
6. 定期用 `audit --verify` 校验链，并异地保存头锚点。
