# 交付指纹（数据水印）设计文档

面向脱敏产物对外交付的**溯源标记**能力。每次交付在不破坏分析可用性、不改变假名映射的前提下植入只有本方能验证的指纹；事后拿到疑似泄露的文件或库，完全离线地给出带置信度的批次归因。

## 1. 威胁模型与硬约束

| 约束 | 落地保证 |
| --- | --- |
| 不破坏脱敏语义 | 受保护列（假名 id、标识、连接键）一律不修改；数值列单格位移不超过一个量子 `q`，且只动选定比例的格 |
| 假名全局统一 | 指纹不触碰任何假名列；同一原始值在全库、跨批次的假名结果完全一致（见测试 `test_pseudonym_mapping_stays_global_and_consistent`） |
| 验证完全离线、不回读原始数据 | 验证只需「嫌疑文件 + 归档清单 + 本地主密钥」；不打开源库、不读假名映射库。`fp-bundle` 可导出仅含清单的离线验证包 |
| 参数留档且可与审计互证 | 每次交付写一份内容哈希封存的清单，并向既有追加式审计链追加一条 `fingerprint_delivery` 记录，钉住清单哈希与产物哈希；`fp-reconcile` 双向对账 |
| 标记不可反推种子 | 清单只存 HMAC 输出与哈希（单元格指纹、锚点摘要、行种子），不存主密钥、子密钥或任何明文行值；每批次用独立派生子密钥，单批清单无法反推主密钥或他批参数 |
| 干净数据不误报 | 单批门限做 Bonferroni 校正（家族误报率 ≤1%），数值通道设最小试验数，金丝雀需多列联合命中；蒙特卡洛测试对多份随机干净数据零误报 |

信任边界：**指纹主密钥**是最高敏感资产，与脱敏管线的假名密钥相互独立，文件权限 `0600`，通过 `MASKLINE_FP_KEY` 或 `--key` 提供。清单不含密钥，但属于内部元数据，不应随产物交付。

## 2. 三通道协同设计

### 2.1 数值微扰（主通道，统计检验）

对每个非受保护数值列配置量子 `q`（可自动取数据跨度约 1% 的整洁网格）。标记判定：

```
网格奇偶位  bit(v) = round(v / q) mod 2
目标位      b = HMAC(子密钥, 交付ID, 列, 行种子, "bit")
```

仅对 HMAC 选定的稀疏行（`mark_rate` 比例），把值移到**最近的、奇偶位等于目标位的网格倍数**，位移量 `≤ q`。未选中的格原样不动，把扰动预算集中在承载比特的格上。整数列只产生整数位移。

验证时对幸存的被选格做**单侧精确二项检验**：零假设下每格以 1/2 概率偶然匹配。行过滤只减少试验数，列裁剪只减少参与的列，类型转换（货币符号、千分位、科学计数法、百分号）由容错解析器归一化后网格奇偶位保持不变。

### 2.2 金丝雀行（高置信通道）

每批插入若干 HMAC 生成的合成行：

- 键列与假名列使用与真实假名同形（`psn_` 前缀）的全新 keyed token，不与任何真实锚点值碰撞；
- 数值哨兵刻意落在真实观测范围**之外**（最大值外 1–4 个网格步，仍在合理量级），使真实行几乎不可能复现；
- 清单只存各单元格的 keyed 指纹（`cell_fingerprint`）与行指纹，不存明文。

键列存活时按键 token 识别金丝雀行；键列被裁时退化为**数值哨兵多列联合匹配**（默认要求同一行 ≥3 个数值列同时命中），低基数分类列在该模式下被显式忽略，避免真实行共享分类值造成假命中。

### 2.3 行序编码（辅助通道）

对每行按 HMAC 秩做稳定排序，相邻行的相对方向承载 O(n) 个比特。攻击者保持原顺序时该通道可加权佐证；一旦洗牌或重新导出，相邻关系被破坏，通道自动塌缩回随机水平（约 50% 一致），**不会产生伪证**，主通道与金丝雀通道不受影响。

## 3. 行身份与后备锚点（抗键列裁剪）

所有标记不直接绑定键值，而是绑定一行秘密**行种子**：

```
行种子 = HMAC(子密钥, "row-seed", 交付ID, 数据集名, 稳定键文本)
```

- 键列存活：直接由键值重算行种子；
- 键列被裁：对唯一的受保护列（如账户假名）在嵌入时构建锚点索引，每项为 `{锚点值的 keyed 摘要, 行种子}`，只收录在该列上取值唯一的列（低基数列自动跳过）。验证时用嫌疑行的锚点值算摘要反查行种子。

锚点索引只存摘要与 HMAC 种子，不含明文；唯一的未解析行是金丝雀（其锚点 token 本就不在真实行索引中）。

## 4. 统计与置信度

- **精确二项尾概率**：用正则化不完全 Beta 函数计算，小样本下仍准确，不用正态近似；
- **p 值合并**：数值、金丝雀、行序三通道独立 p 值用 Fisher 法合并，全程对数空间运算避免下溢；
- **多重检验**：K 个归档批次时单批门限为 `0.01/K`（Bonferroni），家族误报率受控；
- **置信带**：`no_match / possible / likely / very_likely / confirmed`，强结论要求最少 20 个幸存试验或金丝雀命中；
- **混合比例**：本批行匹配概率≈1，外来行≈1/2，故真实份额 `f = 2×匹配率 − 1`，并给出 Wilson 置信区间；
- **混库归因**：各批次独立评分，不强制单选；多批显著时报告 `mixed` 并按份额标注主成分。

## 5. 抗攻击矩阵

| 攻击 | 数值通道 | 金丝雀 | 行序 | 结论 |
| --- | --- | --- | --- | --- |
| 随机行过滤（含删 30%+） | 幸存格继续检验 | 幸存金丝雀仍可识别 | 相邻关系部分保留 | 可归因，试验数随留存率下降 |
| 列裁剪（保留键） | 剩余数值列继续 | 剩余单元格继续 | 不受影响 | 可归因 |
| 列裁剪（连键列一起裁） | 后备锚点还原行种子 | 数值哨兵联合匹配 | 锚点还原秩 | 可归因（需存在唯一受保护锚列） |
| 类型/格式转换（CSV↔JSONL↔SQLite、货币格式） | 容错解析保网格奇偶 | 指纹按规范化值计算 | 顺序若保留则有效 | 可归因 |
| 多批数据混合 | 各批独立二项信号 | 各批金丝雀独立命中 | 失效 | 多批同时检出，给主成分与份额 |
| 行洗牌 | 不受影响（按行种子） | 不受影响 | 塌缩为随机，不做伪证 | 主通道独立成立 |
| 拿到清单但无主密钥 | 无法重算任何 HMAC/指纹 | 同左 | 同左 | 无法验证也无法伪造 |
| 干净/未交付数据 | 匹配率≈50%，过门限失败 | 零命中 | 随机 | 明确 `no_match` |

## 6. 操作流程

```bash
# 1. 生成主密钥（仅一次，0600，离线备份）
maskline fp-keygen --workspace .

# 2. 每次交付：植入并自动留档 + 写审计
maskline fp-embed --workspace . --config fp-config.yaml \
  --input leads.masked.csv --output delivery-vendor-A.csv \
  --delivery-id vendor-A --recipient 外包商甲

# 3. 事后离线归因（支持 csv / jsonl / sqlite）
maskline fp-verify --workspace . --suspect leak.csv --json report.json

# 4. 清单与审计链对账
maskline fp-reconcile --workspace .
maskline audit --verify

# 5. 导出气隙验证包（默认不含密钥）
maskline fp-bundle --workspace . --out bundle.zip
```

`fp-verify` 退出码：`0` 检出匹配，`3` 明确无匹配，`2` 运行错误——便于接入自动化流程。

## 7. 配置说明

见 `policies/fingerprint-example.yaml`。要点：

- `key_column`：主键（行身份首选锚），永不修改；
- `protected_columns`：假名/标识/连接键，永不修改，其中取值唯一的列自动成为后备锚；
- `numeric_columns`：承载主通道的数值列，`quantum` 留空即自动选网格，`integer: true` 保证整数语义；
- `canary_columns` / `canary_count`：金丝雀可用的分类列与数量；
- `min_rows`：数据量下限，低于该值统计功效不足直接拒绝植入。

## 8. 局限与不适用场景

- 若攻击者裁掉**所有**唯一受保护锚列且键列，又只保留低基数分类列，行身份无法还原——部署时应保证交付物中至少保留一个唯一假名列；
- 数值微扰是量化网格级别的可控扰动，不是差分隐私；不提供正式的 k-匿名/差分隐私保证；
- 全表数值列被聚合（求和、求均值后只交汇总结果）时行级标记不复存在，本方案针对行级/库级产物；
- 主密钥丢失则历史批次永久无法验证；主密钥泄漏则攻击者可验证但仍无法据此还原原始敏感数据（清单与标记均不含明文）。
