# 跨数据集敏感关联风险识别（linkage）

`maskline linkage` 子包提供独立的跨数据集敏感关联风险识别能力，解决单数据集
敏感识别的一个盲区：某些字段单独看并不敏感，但多个离线数据集通过唯一标识类
字段（手机号、身份证号、会员号等）关联之后，组合出的信息属于高度敏感。本能力
自动扫描目录下的全部离线数据集，识别跨文件的等值关联与语义关联，计算关联后
敏感组合的风险等级，输出关联关系图谱与风险点清单，用于指导脱敏规则配置。

全程**只读**源数据集，不会修改任何原始文件。

## 快速开始

```bash
# 一键演示：生成带跨库关联键的合成数据并扫描
python -m maskline linkdemo

# 扫描指定目录（增量：只重新画像新增/修改的数据集）
python -m maskline linkscan data/raw

# 扫描并导出建议脱敏策略（可直接交给 maskline run --policy 使用）
python -m maskline linkscan data/raw --export-policy

# 查看最新版本的关联图谱与风险清单（不重新扫描）
python -m maskline links
```

## 处理流程

```
目录扫描 ──> 增量判定 ──> 并发列画像 ──> 关联匹配 ──> 图谱聚类 ──> 组合评级
           (指纹比对)    (fd 预算)     (等值/语义)   (数据集级)   (组合规则)
                                                              │
              版本化存储 linkgraph.sqlite <────────────────────┘
              报告 reports/linkage/linkgraph-vN.{md,json}
              建议策略 linkgraph-vN.policy.yaml（可选）
              审计留痕 audit.jsonl（贯穿全程）
```

### 1. 列画像（整合单库敏感识别 + 字段指纹）

每个数据集单遍采样（默认 500 行），逐列：

- 复用现有 `detectors` 引擎打分（score = 命中率 × 校验通过率，高/中/低置信度），
  与 `maskline scan` 的单库识别结果完全同源；
- 统计 distinct 数与 distinct 比率；
- 判定**键候选**（唯一标识类字段），满足任一条件即可：
  - 识别为标识类敏感类型（身份证、手机号、邮箱、银行卡、统一社会信用代码）；
  - 列名像键（`*_id`、`*_no`、`*_code`、编号、卡号、工号等）且 distinct ≥ 10；
  - distinct 比率 ≥ 0.9 且值形态像 ID（纯数字或短字母数字串，排除日期形态）；
- 仅对键候选列存储**值集指纹**（规范化后逐值 sha256，每列最多 5000 个），
  用于跨库等值匹配。原始值不落盘。

画像同时回写现有 `Catalog`（meta.sqlite），与 `maskline scan` 的登记/发现结果
保持一致，一次扫描两处可用。

### 2. 关联匹配

- **等值关联**：对全部键候选列的值指纹建倒排索引，跨数据集列对若共享值数
  ≥ 3 且较小值集在较大值集中的包含度 ≥ 0.6（可调），则建立等值边。
  对**无敏感类型的纯代理键**（如自增 id），额外要求列名共享非泛化实体词
  （`member_id`↔`member_id` 通过，`member_id`↔`order_id` 拒绝），避免
  整数区间天然重叠造成的伪关联。
- **语义关联**：不同数据集中敏感类型相同的列（如两处 `person_name`），或
  列名落入同一同义词组（phone/mobile/电话…）的未识别列，建立语义边。
  语义边是"含义相近"的提示，不参与 Join 聚类。

### 3. 图谱聚类（关联关系建模）

只要 A 库某列与 B 库某列等值关联，两库全部字段即处于同一可关联组合。
因此对**数据集**做并查集连通分量，每个跨库连通分量即一个关联集群，
集群的敏感组合 = 集群内全部数据集的敏感字段并集。

### 4. 组合风险评级（兼容现有打分规则）

- 类型权重：id_card 1.0、bank_card 0.9、mobile_phone 0.8、credit_code 0.7、
  address 0.7、person_name 0.6、email 0.5、ipv4 0.3；
- 组合得分 = 1 − Π(1 − 权重 × 该类型最高列得分)（noisy-or）；
- 基础等级沿用现有置信阈值：≥0.8 高、≥0.5 中、≥0.2 低；
- **组合规则升级**：命中已知高危组合时提升等级，最高到"极高"（critical）：

  | 组合 | 等级 | 说明 |
  |---|---|---|
  | 姓名 + 身份证 | 极高 | 实名身份核验组合 |
  | 姓名 + 银行卡 | 极高 | 资金账户实名组合 |
  | 身份证 + 银行卡 | 极高 | 金融账户控制组合 |
  | 银行卡 + 手机号 | 高 | 账户触达组合 |
  | 姓名 + 手机号 | 高 | 联系触达组合 |
  | 姓名 + 地址 | 高 | 居住地址画像组合 |
  | 手机号 + 地址 | 中 | 行踪联络组合 |
  | 姓名 + 邮箱 | 中 | 通讯身份组合 |
  | 姓名 + 信用代码 | 中 | 企业自然人关联组合 |

- 同一集群出现 ≥2 类敏感字段时，等级不低于"中"。

### 5. 输出

- `reports/linkage/linkgraph-vN.md`：风险点清单（等级/组合/涉及数据集/关联键/
  管控建议）、关联关系图谱（集群、字段、等值边）、语义关联提示、跳过文件告警；
- `reports/linkage/linkgraph-vN.json`：上述内容的结构化版本（节点/边/集群/风险）；
- `reports/linkage/linkgraph-vN.policy.yaml`（`--export-policy`）：按风险等级
  生成的建议脱敏策略，通过 `policies.py` 严格校验，可直接复核后用于
  `maskline run --policy`。等级为极高时标识类字段建议 `hash`，其余按类型
  给出 pseudonym/mask/generalize 等建议。

## 增量更新与版本化存储

所有结果存于 `data/linkgraph.sqlite`：

- `dataset_state` 按路径记录内容指纹、大小、mtime 与状态
  （active/removed/ignored/error）；
- 再次扫描时：大小与 mtime 未变 → 直接复用画像（零 I/O）；已变化 → 重算内容
  指纹，指纹未变只刷新元数据，指纹变了才重新画像；消失的标记 removed；
- 列画像与值指纹按**内容指纹**存储，内容相同的文件天然共享画像；
- 每次扫描生成新版本号，边与风险按版本归档，历史版本可随时用
  `python -m maskline links --version N` 回看；
- `--full-rescan` 可强制全量重画像。

## 并发与文件句柄控制

- 画像阶段使用有界线程池（`--workers`，默认 4）；
- 另有独立的**文件句柄预算**信号量（`--max-open-files`）：默认取进程
  `RLIMIT_NOFILE` 软限制的 1/8（夹在 4..32），任何时刻打开的数据集文件
  不超过预算，扫描大量小文件不会撑爆句柄限制；
- 源数据集始终以只读方式打开（SQLite `mode=ro`），每个文件用完即关。

## 容错与告警

文件级异常（编码错误、文件损坏、读取失败）只跳过该文件：

- 记入本次扫描的告警清单（报告"跳过文件告警"一节 + `warnings` 表）；
- 写入审计链 `linkscan_file_skipped` 事件（超过 20 条时折叠为汇总事件）；
- 已知数据集变为不可读时状态置为 `error`，其旧画像立即从图谱中剔除，
  下次扫描自动重试；
- 整体扫描任务不中断。

## 操作留痕

每次扫描向现有审计哈希链追加事件：`linkscan_started`（目标、参数、忽略规则
指纹）→ `linkscan_file_skipped`（每个跳过文件）→ `linkscan_completed`
（版本号、文件统计、边数、风险数、各级别数量）→ `linkscan_policy_exported`
（如导出策略）。可用 `python -m maskline audit --verify` 校验链完整性。

## 忽略规则

通过 `--ignore-rules rules.yaml` 排除已知的非关联字段，降低误判：

```yaml
version: 1
ignore:
  datasets:              # 整个文件不参与关联扫描（路径 glob）
    - "scratch/*"
  columns:               # 指定字段不参与匹配与组合（<路径 glob>:<表>.<列>）
    - "demo.sqlite:customers.notes"
    - "*:orders.status"
  pairs:                 # 指定字段对不建立等值关联
    - ["a.sqlite:t1.c1", "b.sqlite:t2.c2"]
  sensitive_types:       # 指定敏感类型不参与组合评级与语义关联
    - "ipv4"
```

被忽略的列仍会做敏感识别并写入 Catalog（单库视角的事实不变），但不参与
跨库匹配、聚类与风险评级。忽略规则的指纹会记入审计与扫描记录。

## 安全说明

- `linkgraph.sqlite` 中的值指纹是低熵域（手机号、身份证）可暴力枚举的
  sha256，应与 `pseudomap.sqlite` 同等保护，不要随脱敏产物一起外发；
- 报告遵循最小暴露原则：只展示字段元数据与统计量，不展示原始值；
- 本能力不联网、不写源数据。

## 已知限制

- 等值匹配基于采样（默认前 500 行）与值指纹，超采样窗口后才出现的关联值
  可能漏检，可调大 `--sample-limit`；
- 纯代理键改名（`cust_id` ↔ `customer_id`）且无敏感类型时不会建立等值边；
- 相同内容的文件按指纹去重，视为同一数据集；
- 语义关联仅为提示，需要人工复核确认是否构成真实关联维度。
